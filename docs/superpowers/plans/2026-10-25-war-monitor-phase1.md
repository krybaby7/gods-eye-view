# War monitor Phase 1 implementation plan (collect, digest, map)

> **For agentic workers:** Read `docs/superpowers/specs/2026-10-25-war-monitor-design.md` first; it is the spec (records, registry, digest protocol, code-owned fields, UI). Then `2026-10-25-news-integration-options.md` section 1 for the template files. Root integrates and reviews; subtasks may run in parallel where files do not overlap.

**Goal:** Feeds from the curated directory are collected continuously; pressing Refresh runs one Claude Sonnet 5.5 digest through Perplexity that turns the new items into stories; each located story is one pin on the globe, filterable by category; every story expands to its cited items with publisher, perspective and verification label computed by code.

**Architecture:** Node provider `server/providers/news/` (fetchers, item store, gazetteer, digest runner, story computation, routes). Browser layer `src/layers/news/` draws stories through a `CustomDataSource` and the world-overlay host and exposes `getSnapshot()` / `subscribe()` to `src/ui/situationPanel.js`. No database, no Python, no timer-driven LLM calls.

**Tech stack:** Node 24, Vite middleware plugins, installed Cesium, `node:test`, repository QA scripts. Perplexity Agent API (`@perplexity-ai/perplexity_ai` or raw fetch) with `model: "anthropic/claude-sonnet-5-5"`, no search tools, strict JSON schema output.

**Decisions already made:** Telegram previews allowed; ReliefWeb behind `RELIEFWEB_APPNAME`; digest only on Refresh; daily budget cap `NEWS_DIGEST_DAILY_BUDGET_USD` default 2.00; Google News RSS stays cockpit-only; the model never returns URLs or coordinates that code trusts without a gazetteer match.

## Out of scope for Phase 1
Evidence-nearby counts, per-story deep dive with web search, corrections tracking, SQLite history, media-ownership badges, additional theaters. Schema fields that these need already exist and stay empty.
