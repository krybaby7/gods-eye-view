# World theater: political news worldwide

Date: 2026-10-28. Status: design, agreed with the owner, not built. Overnight cloud task.
Builds on `docs/WAR-MONITOR.md`, `2026-10-25-war-monitor-design.md` and
`2026-10-28-situation-brief-design.md`.

## 0. Shape in one paragraph

The war monitor covers one region (Iran, Israel, the US and their fronts). The owner's goal is a
clear, up-to-date map of political news worldwide. This adds a second theater, `world`, that
collects from global and regional outlets on every continent, places stories on a worldwide
gazetteer (every country, every capital, major cities and named political hotspots), and sorts
them into political categories. It reuses everything the war monitor already has: collection,
the Refresh digest, one pin per story, verification labels, the Situation panel and its theater
menu. No new mode and no new layer: the owner picks "World" in the panel's theater menu.

## 1. Decisions (owner, 2026-10-28)

- Worldwide coverage is the biggest gap; this is the first step. A zoomed-out "hotspot" view is
  a later task.
- Refresh stays manual (no timer); the existing daily budget covers every theater.
- The existing theater (`iran-israel-us`) stays as it is.

## 2. The theater file (`public/news/theaters/world.json`)

Same schema as `iran-israel-us.json`, validated by `server/providers/news/registry.js`.

- `id: "world"`, `name: "World"`.
- `brief` (the scope note sent with every digest): neutral and short. It describes what counts
  as political news (elections, governments and courts, protests and unrest, armed conflict,
  diplomacy and sanctions, coups, humanitarian crises caused by conflict or politics) and says
  nothing about sides.
- `categories` (one colour each, distinguishable from each other and readable on the globe):
  `armed-conflict`, `elections-governance`, `protests-unrest`, `diplomacy-sanctions`,
  `humanitarian`, `rights-justice`.
- `perspectives`: a list of perspective ids with groups. Groups drive corroboration (two items
  from different groups, at least one independent, humanitarian or verification, with distinct
  primary sources), so design them on purpose:
  - one `international` group for global wires and broadcasters;
  - one group per region (`africa`, `asia-pacific`, `europe`, `latin-america`, `middle-east`,
    `north-america`, `south-asia`, `eurasia`) for national and regional outlets;
  - a `state` group for state-controlled outlets of any country (kind `state`);
  - `un` and `ngo` for humanitarian bodies;
  - `analysis` for think tanks and conflict monitors.
- `actors`, `drivers`, `tracks`: omitted (empty). The Situation Brief is built around one
  crisis, so the World theater turns it off (section 5).
- `gdeltTerms`: a short list of political terms (election, protest, coup, sanctions, ceasefire,
  parliament and similar). Every GDELT query must stay within `GDELT_MAX_QUERY_CHARS`, which
  `src/data/newsFetchers.test.mjs` checks for the live registry.
- `sourceIds`: section 3.

## 3. Sources

Add sources to `public/news/sources.json` and list them in the theater. Reuse existing entries
where the outlet is already registered (Al Jazeera, Reuters, AP and others): a source can belong
to several theaters.

- **Target:** 30 to 45 sources. At least three per region group, two or more `international`
  sources, a few `state` outlets clearly marked (kind `state`, with a `caution` line), UN News,
  and Crisis Group (CrisisWatch).
- **Transports allowed:** `rss`, `gdelt-domain`, `reliefweb` and `link-only`, as today. Never
  scrape a bot-protected site. Never use Google News RSS (that stays confined to the cockpit).
  Headline, snippet, link and publisher only.
- **Probe every feed** from the cloud machine with the app's own fetcher and parser
  (`server/providers/news/fetchers/rss.js`, `server/providers/common/rss.js`). Record the date
  of each feed's newest entry in a table in the PR. A feed whose newest entry is older than
  72 hours is not added (the collector would only mark it `quiet`).
- Every new source gets a `DATA_CREDITS` entry and a `DATA_SOURCES.md` row. The tests in
  `src/data/newsCredits.test.mjs` enforce both.
- Each source carries `folder`, `kind` and `perspective` like the existing ones. A wrong kind
  breaks the verification labels, so choose carefully: independent outlets are `independent`,
  state-controlled ones are `state`, and parties to a conflict are `participant`.

## 4. Gazetteer

A worldwide gazetteer generated by a script and committed as data.

- **Script:** `scripts/build-world-gazetteer.mjs` reads Natural Earth's public-domain data
  (admin-0 countries and populated places) and writes the `gazetteer` array of `world.json`. It
  runs by hand; the committed data is what the app uses.
- **Rows:**
  - every country (precision `country`, coordinates at a sensible label point, not a
    geometric centroid in the sea);
  - every capital (precision `city`);
  - cities of 1 million people or more (`city`);
  - a hand-written list of about 40 named political hotspots and regions, each with its
    source noted in the script (Gaza, West Bank, Donbas, Crimea, Kashmir, Darfur, Sahel,
    Taiwan Strait, South China Sea, Nagorno-Karabakh, Tigray, the Rohingya areas of Rakhine,
    and similar), precision `region`.
- **Aliases:** the English name plus native and major-language names from Natural Earth (Arabic,
  Persian, Hebrew, Russian, Chinese, Spanish, French, Portuguese). Drop any alias that would make
  `validateGazetteer` report an ambiguous spelling, and drop ambiguous place names (Georgia the
  country versus the US state). Log the dropped ones.
- **Credit:** add Natural Earth to `DATA_SOURCES.md` and the credits.

## 5. Code changes

Keep them small; most of the work is data.

- **Prompt size.** `buildDigestInstructions` in `server/providers/news/digest/runner.js` lists
  every gazetteer name and alias in the digest instructions. With a worldwide gazetteer that
  would add tens of thousands of input tokens to every Refresh, which costs money because
  Perplexity charges a cache-write fee on the whole input each run.
  - Add an optional `prompt: true` flag on gazetteer rows. When any row has it, the
    instructions list only flagged rows, by name, without aliases. The world script flags
    countries and capitals only.
  - Code still resolves places against the full gazetteer with all aliases.
  - Report the measured size of the World digest instructions, in characters and estimated
    tokens.
- **Situation Brief off for World.** Add an optional theater flag `situationBrief: false`.
  - When it is false, no brief call runs after a digest, Retry brief is hidden, and the panel's
    Brief section shows nothing for that theater.
  - Default `true`, so `iran-israel-us` is unchanged.
  - A world-wide briefing is a later design.
- **Theater menu.** The Situation panel already lists theaters from `GET /api/news`. Check that
  switching to World and back works: pins, category chips, stories, Raw feed, and Frame theater
  (for World it should frame the whole globe sensibly).
- Register any new module in `scripts/package-boundaries.json`.

## 6. Out of scope

- A world Brief.
- The zoomed-out hotspot view.
- Changes to the GDELT transport: a parallel task rewrites it, so don't edit
  `server/providers/news/fetchers/` or `server/providers/news/collector.js`.
- Changes to `iran-israel-us.json`.

## 7. Tests and verification

- **Registry:** `world.json` validates. Every source id exists, every perspective is declared,
  categories are unique, and no gazetteer spelling is ambiguous.
- **Prompt size:** the instructions list only `prompt: true` rows when any exist, and every row
  otherwise (existing behaviour).
- **Brief flag:** with `situationBrief: false`, a successful digest runs no brief and records no
  brief run. With the flag absent, behaviour is unchanged.
- **Geocoding:** a fixture digest for World resolves:
  - a country ("Sudan" → country precision);
  - a capital ("Caracas");
  - a hotspot ("Donbas" → region);
  - an alias in another script ("Москва" → Moscow).
- **QA:** `scripts/qa-news.mjs --fixtures` gains a World run: switch theaters, see pins and
  category chips, Frame theater, Cyber theme, 720 px and 390 px.
- `npm test`, `npm run build`, `npm run format:check`, `npm run check:boundaries`,
  `npm run layer-token:check -- --base-ref origin/main`.
- No live digest: the cloud machine has no Perplexity key. Report the estimated input tokens
  and cost for a 400-item World digest from the instruction size and the measured item sizes.
